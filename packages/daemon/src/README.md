# Daemon Source

The LobsterFarm daemon process. Manages entities, spawns Claude Code agent sessions, routes Discord messages, and exposes an HTTP API for the CLI and Commander to interact with. Runs as a macOS launchd service.

## Files

- `index.ts` -- Entrypoint. Wires up all subsystems (registry, sessions, queue, Discord, Commander, pool) and handles graceful shutdown.
- `config.ts` -- Loads and validates the global `~/.lobsterfarm/config.yaml` file.
- `registry.ts` -- `EntityRegistry` class. Scans `~/.lobsterfarm/entities/` on startup, validates each entity's `config.yaml`, and provides lookup by ID.
- `session.ts` -- `ClaudeSessionManager`. Spawns Claude Code as child processes with the correct agent, model, DNA, permissions, and entity context. Tracks active sessions, captures output, emits lifecycle events.
- `queue.ts` -- `TaskQueue`. Priority-ordered queue that feeds sessions to the session manager, respecting the configured concurrency limit. Processes next task when a slot opens.
- `server.ts` -- HTTP API server. Routes for status, entities, tasks, pool management, entity scaffolding, reload, webhook endpoints, and the per-PR review-lease API (`GET review-state`, `POST`/`DELETE review-lease`).
- `router.ts` -- Discord message router. Deterministic rules: channel-type routing (alerts, general), keyword-based intent classification. Legacy `!lf` prefix parsing retained for test coverage.
- `discord.ts` -- `DiscordBot` class. Connects to Discord via discord.js, builds a channel-to-entity index from entity configs, handles incoming messages via the router, sends messages as webhooks for agent identity, and scaffolds new entity Discord categories/channels.
- `commander-process.ts` -- `CommanderProcess`. Manages Pat (the Commander) as a persistent Claude Code session inside a tmux session with the Discord channel plugin. Health-checks every 10s (tmux death + MCP plugin-liveness deafness, issue #77), auto-restarts with exponential backoff, and resumes the persisted session on recovery.
- `pool.ts` -- `BotPool`. Manages a pool of Discord bot accounts (pool-0 through pool-N) for assigning to channels. Handles assignment, release, LRU eviction, parking (session preservation), nickname setting, pre-assignment of planners to entity #general channels, and the MCP plugin-liveness deafness probe (issue #73). A deaf verdict auto-recycles the channel release-to-fresh — the same release + assign an operator does by hand — with a per-channel loop guard (#106); `heal_post_restart` is the one-shot post-restart pass that recycles resumed sessions showing zero turn evidence since their resume nudge (the 08-01→08-04 "alive but receiving nothing" incident class), with an aggregate operator alert.
- `gateway-watchdog.ts` -- `GatewayWatchdog` (#107). Heartbeat-recency liveness for the daemon's single Discord gateway: samples shard heartbeat-ack timestamps (`shard.lastPingTimestamp`, discord.js v14) on a timer and, on sustained silence (default 3 missed heartbeat intervals ≈ 2 min) with no discord.js reconnect in flight, destroys and re-logs-in the client. Sentry event fires FIRST (Discord itself may be the sick component), then a best-effort Discord alert. Not broker-flag-gated — protects today's gateway too. Probe/recycle/clock all injectable; `DiscordBot` hosts the probe and the recycle.
- `plugin-liveness.ts` -- Shared MCP plugin-liveness probe logic (issues #73, #77). `evaluate_plugin_liveness` is a pure verdict function comparing inbound/processing timestamps against tmux pane-idle state to detect a "deaf but alive" session; `is_tmux_session_idle` reads the pane. Consumed by both `pool.ts` and `commander-process.ts` (re-exported from `pool.ts` for existing importers).
- `actions.ts` -- Side-effect functions: git worktree create/cleanup, GitHub PR create/merge via `gh`, test runner, and Discord notification dispatch.
- `worktree-cleanup.ts` -- Worktree removal: post-merge cleanup (`cleanup_after_merge`) and the hourly stale sweep (`sweep_stale_worktrees`). Four independent gates stand between a worktree and deletion, and all four fail toward *keeping* it. (1) **Live-agent shield** (#110): a worktree root holding `.lf-agent-active` is never removed, by any path, with no alert and no tmux relocation -- see "Live-agent shield" below. (2) **Unstarted-branch classifier** (#110): a branch whose tip sits on the trunk's first-parent history has produced no commits of its own, so it is unstarted rather than finished; an unresolvable trunk abandons the whole repo. (3) **#27/#30 safety preconditions**: no uncommitted changes, no untracked files, no commits unreachable from any remote ref -- a failure here skips the removal and posts an action-required alert. (4) **Branch identity**: `remove_worktree` is only ever called with the branch actually checked out in the directory being deleted, because #30's unpushed check is evaluated against the branch it is given. `.claude/worktrees/` directories are therefore matched on the branch git reports for the directory itself -- never on their name (those are the Claude Code harness's `EnterWorktree` worktrees, named randomly `agent-<hex8>` with no relation to any branch) and only once the directory is confirmed to be the root of a working tree belonging to *this* repo, because `git symbolic-ref` answers for whatever repository encloses a path. `remove_worktree` enforces the invariant itself rather than trusting callers. Known limitation: fast-forward-merged and squash-merged worktrees are never reclaimed automatically; both are documented in the source, and the reclaim path is issue #129.
- `review-utils.ts` -- Utility functions for PR review feedback: fetch review comments from GitHub and build fix prompts for the auto-fix loop.
- `hooks.ts` -- Post-session hooks. Extracts session learnings via Haiku and appends them to daily logs. Also manages the global learnings file.
- `models.ts` -- Maps abstract model tiers (opus/sonnet/haiku + think level) to Claude CLI flags.
- `persistence.ts` -- JSON file persistence for PR review state and pool state. Saves to and loads from `~/.lobsterfarm/state/`. `load_pr_reviews` sanitizes on load (#102 Gap 3) -- malformed / mismatched / unknown-entity keys are dropped, logged, and the file rewritten clean (self-healing against leaks like a bogus `lobster-farm:6010`). Under `NODE_ENV=test`, the save functions refuse to write when the state root resolves to the real `~/.lobsterfarm` (forces tests to sandbox `paths.lobsterfarm_dir`).
- `pid.ts` -- PID file management. Write, read, remove, and check if the daemon is already running.
- `singleton.ts` -- Singleton port guard (issue #97). `acquire_port` binds `:7749` up-front (before Discord/pool/commander start) and returns the listening server for `start_server` to reuse; on `EADDRINUSE` it logs a single line and exits 0 (deliberate stand-aside) instead of crash-looping. `classify_listen_error` is the pure decision function (unit-tested).
- `log-rotation.ts` -- Size-based log rotation (issue #97). `rotate_log_if_needed` renames `daemon.log` to `daemon.log.1` on startup when it exceeds the cap (25 MB default), because launchd never rotates its `StandardOutPath`. Best-effort; keeps a single backup to bound disk usage.
- `pr-cron.ts` -- `PRReviewCron`. Polls entity repos for open PRs, spawns headless reviewer sessions, and routes outcomes (approve/merge, fix, escalate). Acquires a `ReviewLeaseStore` lease (`daemon-cron`) before spawning so it never collides with the webhook or manual review paths, and **holds that lease through the merge** — every merge site is gated by `assert_can_merge` (#102), so an auto-merge can't fire while another review is in flight. `should_skip_pr` counts only genuine reviewer feedback (formal reviews + the reviewer identity's `**Verdict:` comments), so a PR author's own comment after a push never suppresses re-review (#102 Gap 2).
- `webhook-handler.ts` -- GitHub webhook handler. Receives PR events, verifies signatures, maps repos to entities, and spawns reviewer/fixer sessions. Acquires a review lease (`daemon-webhook`) before spawning and holds it through post-review routing; every merge site (v1 auto-merge + v2 `run_merge_gate`) is gated by `assert_can_merge` (#102). The lease is released only after routing completes, before any SHA-move requeue.
- `review-lease.ts` -- `ReviewLeaseStore`. In-memory per-PR review mutex (issue #60). A lease (key `owner/repo#num`) is acquired by one of three holders -- `daemon-cron`, `daemon-webhook`, `tidus-manual` -- before a reviewer spawns, so two reviewers never run on the same PR. The lease also **gates the merge, not just the spawn** (#102): `holds()` + the `assert_can_merge()` helper let every merge call site confirm the caller still owns the live lease before merging (fail-open when the store is absent). Lazy TTL expiry (20 min default, tunable via `pr_cron.review_lease_ttl_ms`); no disk persistence, no background sweeper.

## Live-agent shield

To pin a worktree against the hourly sweep, create `.lf-agent-active` in its root:

```
touch /path/to/worktree/.lf-agent-active
```

The sweep then skips it unconditionally -- no removal, no branch delete, no tmux `cd`, and no alert (it is deliberately held, not stuck). Delete the file to release it. There is no grace period and no expiry: a marked worktree stays until the marker goes, so a marker left behind by a crashed agent pins its worktree indefinitely (issue #129 covers adoption, visibility, and expiry).

The marker is honored regardless of git ignore state -- it is checked with `stat`, not `git status`. **Do not commit it**: it is per-worktree, transient state.

## Key Concepts

- **Session spawning**: The daemon never runs Claude Code interactively. It spawns headless sessions with `--output-format stream-json` and pipes the prompt via stdin.
- **Bot pool**: Discord bot accounts are a limited resource. The pool assigns them to channels on demand, evicts via LRU when full, and parks sessions for later resume.
- **Commander (Pat)**: The only agent that runs persistently. Lives in a tmux session, connected to Discord via the channel plugin, operating at the platform level rather than entity level.
- **PR review loop**: PRs are reviewed by spawning headless reviewer sessions. If changes are requested, a builder is spawned to fix. GitHub issues and PRs are the source of truth.
